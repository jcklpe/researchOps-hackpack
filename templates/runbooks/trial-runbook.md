# Trial Runbook
Use this when the researcher chooses a new round of work within an existing project. Confirm the trial name, project, and chosen method.

## Setup Checklist
- [ ] Create a trial folder with a blank brief, the selected method's plan, a report, and `artifacts/`, manually or with the trial-creation skill.
- [ ] Create the [trial brief and plan](tasks/trial-brief-and-plan.md) task.
- [ ] Create the [recruitment](tasks/recruitment.md) task, with scheduling for interviews/user tests or distribution preparation for a survey.
- [ ] Create the [data collection](tasks/data-collection.md) task, using sessions or a survey response window as appropriate.
- [ ] Create the [synthesis and report](tasks/synthesis-and-report.md) task.
- [ ] Group all four tasks under the project's grouping or epic. Link the trial folder and relevant documents from them.
- [ ] Assign owners and reviewers; record the handoffs and dependencies below. Check that everyone can find their next action.

## Handoffs
The researcher drafts the brief and plan, requests team review, revises, and requests the agreed stakeholder review. Resolve required changes before proceeding with collection. Recruitment prepares the selected participants or distribution channel; collection follows the reviewed plan. Synthesis and reporting follow the available evidence, with team feedback and an agreed stakeholder handoff before completion. Return responsibility to the researcher when revisions are needed. Record a role as not applicable when the project's review arrangement does not use it.

The tasks describe the work; an agent copying templates does not perform or approve these stages.
